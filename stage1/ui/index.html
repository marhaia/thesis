GUI Layout Complexity Analyzer

Analyze the visual and structural complexity of a GUI screenshot. The result combines measured visual features, model-estimated saliency and project-specific screenshot proxies into an experimental layout-complexity index.

Scope: This is a screenshot-based computational proxy, not a validated measure of human cognitive load, workload, difficulty or performance.

How it works

Why this pipeline

A transparent, reproducible screenshot-analysis boundary instead of an opaque human-outcome prediction

The project contribution is the explicit integration of image-derived visual features, finite normalized UMSI++ descriptors and declared HCEye-informed screenshot proxies into one inspectable x19 vector. Every computed value, formula, implementation lineage and runtime identity can be shown at the point of use. Task, time-pressure and Big Five study context remain outside the numerical path. The pipeline therefore supports later human validation without presenting the current index as measured cognitive load.

The numerical result follows one screenshot-only path. Optional study context is recorded beside the analysis and has no score effect.

Research Roadmap

The current thesis freezes a bounded screenshot-based proxy first. Human evidence is the gate before context can become a calibrated numerical stage.

Current thesis scope · frozen

Screenshot-based Stage 1

x19 = [v8 | s5 | h6] produces Experimental Layout Complexity. Task, time-pressure and optional study-coded Big Five categories are recorded separately and never modify the score.

  • Reproducible screenshot analysis
  • Saliency map and visual feature profile
  • No claim of validated human cognitive load
Next thesis step

Human Validation

Test how the frozen screenshot proxy relates to subjective, behavioral and gaze-based human outcomes without retuning the score after seeing the data.

  • Predefined analysis plan
  • Task held controlled where possible
  • Task, time-pressure and study-coded Big Five context recorded for empirical analysis
Evidence-dependent development

Empirically Calibrated Stage 2

Only human data can establish whether task type, time pressure or participant characteristics add predictive value beyond Stage 1. Big Five categories require a predeclared validated instrument before interpretation.

  • Estimate effects from human observations
  • No fixed, author-chosen score modifiers
  • Separate development and validation
Longer-term work

Validated Task-Conditioned System

Extend the pipeline only after independent evidence supports the added constructs and intended use.

  • Independent and cross-domain validation
  • Task-conditioned prediction
  • Semantic UI-element detection
  • Validated search and attention outputs
Scope principle: The broader vision is deferred, not discarded. Empirical calibration follows human evidence; it is not assumed inside the current score.
